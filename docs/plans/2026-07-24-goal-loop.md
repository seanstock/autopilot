## Shared contracts (v0.3 additions)

**Project config** gains two optional fields (both default absent):
`verifyCmd` (string shell command; gates every cycle) and `workerModel`
(string; presence enables orchestration for the project).

**Orders** live in `<project>/orders/`, one file per order, filename
`NNN-slug.md` (zero-padded, ascending). Format (exact):

```
# <title>
status: open
created: <iso> by cycle <n>
verify: <command, or - if none>

## Objective
<what to do>

## Acceptance criteria
- [ ] <criterion>

## Boundaries
<files/areas this order may touch>
```

`status:` is line 2 and one of `open|in_progress|done|blocked`. Parsing
rule everywhere: scan the first 10 lines for `/^status:\s*(open|in_progress|done|blocked)\b/`.
Orders are model-written project files (cycles may create/edit them);
they are DISPOSABLE - the orchestrator regenerates rather than repairs.

**Cycle kinds:** `work | critic | wrapup | orchestrate`. A work cycle in
an orchestrated project carries exactly one order. cycle_end events gain
optional fields: `order` (order id string) and `verify`
(`{cmd, ok, code} | null`).

**Kind selection** (scheduler, in priority order; orchestration enabled
means `!!project.workerModel`):
1. forcedKind (wrapup) wins.
2. Pending INJECT.md -> `orchestrate` if enabled, else `work` (directives
   are triaged by the planner, not a worker).
3. Critic cadence (`criticRatio > 0 && cycleNumber % criticRatio === 0`)
   -> `critic` (unchanged, applies in orchestrated projects too).
4. Enabled + at least one `open` order -> `work` with the LOWEST-filename
   open order, and the effective model is `workerModel` (scheduler passes
   `{...project, model: project.workerModel}` to the runner).
5. Enabled + zero open orders -> `orchestrate` (project.model, i.e. the
   big model).
6. Not enabled -> `work` (v0.2 behavior, byte-identical).

**runner.runCycle** opts gain `order: {id, content} | null` (id =
filename without extension; content = full file text). Result gains
`verify: {cmd, ok, code} | null`. Settings file by kind: orchestrate and
critic cycles run with an orchestrate settings variant that additionally
allows the Task tool; work/wrapup use the base variant.

**containment.ensureContainment(project)** returns
`{settingsPath, orchestrateSettingsPath, warning?}`. Base settings =
v0.2. Orchestrate variant = base + `'Task'` in permissions.allow. When
`project.workerModel` is set, also write `<project>/.claude/agents/scout.md`:
frontmatter `name: scout`, `description: Read-only research and
verification subagent. Use for parallel exploration, auditing, and
fact-checking. Never edits files.`, `tools: Read, Glob, Grep, WebSearch,
WebFetch`, `model: sonnet`; body: terse instructions (read-only, return
dense findings, cite files/lines). Cycles cannot edit it (existing
.claude deny rules).

**Verify gate:** when `project.verifyCmd` is set, the RUNNER executes it
after the cycle's child exits and BEFORE auto-commit, `cwd` project dir,
10-minute timeout, `windowsHide`, via `cmd /c` on win32 / `sh -c` posix,
env stripped same as cycles. Result -> `verify.ok` (exit 0), `verify.code`.
Timeout counts as `ok: false, code: null`. Never throws; absent verifyCmd
-> `verify: null`. Per-order `verify:` lines are for the MODEL to run;
the runner only runs the project-level verifyCmd.

**Snapshot:** project entries gain
`orders: {open, inProgress, done, blocked} | null` (null when
orchestration disabled) and `lastVerify: {ok, code} | null` (from the
most recent cycle_end). Server adds
`GET /api/projects/:id/orders` -> `{orders: [{id, title, status}]}`
(title = first line minus `# `; sorted by id; empty array when no dir).
